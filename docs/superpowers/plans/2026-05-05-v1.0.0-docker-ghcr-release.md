# v1.0.0 Docker GHCR Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `bpmt-oauth-demo` 收口为正式 `v1.0.0`，以 Docker 镜像发布到 GitHub Container Registry，并通过 `docker-compose.yml` 在宿主机 `81` 端口运行。

**Architecture:** 保持当前 Node.js/Express OAuth 授权码 demo 主流程不变，发布工作只收口版本元数据、Docker 镜像、Compose 部署契约、README、Release Note 和提示词归档。`docker-compose.yml` 作为正式部署入口，直接声明镜像、宿主机 `81:81` 端口映射和运行配置；容器内部监听端口使用镜像默认值。公开文档只保留密钥占位符，真实密钥由部署者在本机 Compose 文件中替换。

**Tech Stack:** Node.js 20、Express、Docker、Docker Compose、GitHub Container Registry、GitHub CLI、Markdown。

## 当前约束

- 仓库默认分支是 `main`，远端是 `https://github.com/wodenwang/bpmt-oauth-demo.git`。
- 当前 `package.json` 和 `package-lock.json` 版本仍为 `0.1.0`，`v1.0.0` 发布前必须同步更新。
- 当前 `docker-compose.yml` 已把容器端口固定为 `81`，但仍通过 `${VAR:-default}` 和 `.env` 注入配置；正式 `v1.0.0` 要改成配置集中写在 `docker-compose.yml`。
- 当前本地 `main` 比 `origin/main` ahead 1；正式发布前要把已有提交和本次 release commit 一起推送，避免 tag 指向远端不可见历史。
- 上游 BPMT OAuth 文档只支持 OAuth2 Authorization Code，不包含 OIDC、`id_token`、refresh token 或单点登出；本 release 不扩展 OAuth 协议边界。

# bpmt-oauth-demo v1.0.0

## 发布目标

`v1.0.0` 是 `bpmt-lite` OAuth 第三方登录 demo 的第一个正式版本，交付可通过 Docker Compose 运行的示例应用。

## 镜像

- `ghcr.io/wodenwang/bpmt-oauth-demo:latest`

## 运行方式

```bash
docker compose run --rm setup
docker compose up -d app
```

访问地址：

```text
http://localhost:81
```

## 交付范围

- OAuth2 Authorization Code 登录入口、回调、token 换取和 userinfo 读取。
- demo 本地 session。
- BPMT `DEMO_MESSAGE` 动态表初始化。
- 留言登记的查询、新增、查看、编辑、删除和批量删除。

- `docker-compose.yml` 部署入口，宿主机端口映射为 `81:81`，容器内部端口使用镜像默认值。

## 不包含

- OIDC、`id_token`、refresh token。
- 跨系统单点登出。
- BPMT 或 MariaDB 容器编排；本 demo 对接已有 BPMT 和 MariaDB。

## 验证结果

- `npm test`
- `docker compose config`
- `docker build -t ghcr.io/wodenwang/bpmt-oauth-demo:v1.0.0 .`
- `docker pull ghcr.io/wodenwang/bpmt-oauth-demo:v1.0.0`
- 浏览器访问 `http://localhost:81`

## 已知限制

- 运行前必须在 BPMT 后台登记 `client_id=bpmt-oauth-demo`，回调地址必须精确为 `http://localhost:81/oauth/callback`。
- 真实 `client_secret`、`BPMT_API_APP_SECRET` 和数据库密码不得提交到 Git。

### Task 4: GHCR 发布和公开权限

- [ ] **Step 1: 新增后续自动发布 workflow**

Create `.github/workflows/docker-publish.yml`:

```yaml
name: Publish Docker image

on:
  push:
    tags:
      - "v*.*.*"

permissions:
  contents: read
  packages: write

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/metadata-action@v5
        id: meta
        with:
          images: ghcr.io/wodenwang/bpmt-oauth-demo
          tags: |
            type=ref,event=tag
            type=raw,value=latest
      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
```
