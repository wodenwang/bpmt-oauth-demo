# bpmt-oauth-demo v2.0.0 移动端 H5 页面设计

## 背景

`bpmt-oauth-demo` v1.0.0 已经交付可运行的 BPMT OAuth 第三方登录 demo，包含 OAuth 授权码登录、本地 session、`DEMO_MESSAGE` 动态表初始化和留言登记 CRUD。

当前页面以桌面表格为主，移动端只通过 CSS 做了基础折行和横向滚动。v2.0.0 的目标是把主体验重构为移动端 H5 优先，同时兼容 PC 浏览器。这个版本只调整 demo 的页面体验和相关路由，不改变 BPMT OAuth 协议流程。

## 已确认决策

- 版本目标：`v2.0.0`。
- 体验方向：移动端体验优先，但 PC 仍可使用。
- 主界面结构：信息流卡片，不做复杂工作台或底部 Tab 应用。
- 表单交互：新增、查看、编辑使用独立页面，不继续以弹窗作为主流程。
- 技术路线：继续使用当前 `Express + EJS + CSS + 少量原生 JS`，不引入 React/Vite 等前端构建链。

## 目标

1. 手机浏览器打开 demo 后，能顺畅完成登录、查看留言、搜索留言、新增留言、查看详情、编辑本人留言、删除本人留言和退出 demo。
2. BPMT 内嵌 H5/iframe 场景下，页面宽度、滚动、返回和表单交互稳定可用。
3. PC 浏览器使用同一套页面，以更宽卡片布局兼容，不再以传统表格作为主界面。
4. 保留服务端 OAuth、session、权限校验和留言业务规则。
5. 保持本仓库中文文档和提示词归档要求。

## 非目标

- 不实现 OIDC、`id_token`、refresh token、密码模式或跨系统单点登出。
- 不新增 BPMT 自定义 OAuth 端点。
- 不改 BPMT 第三方系统登记方式、`client_id`、`redirect_uri` 精确匹配规则或 Docker Compose 环境变量语义。
- 不把 BPMT 的 `access_token` 暴露给浏览器，也不把它当作 demo 永久会话。
- 不新增独立前端 SPA 构建链。

## 架构设计

v2.0.0 保持现有后端边界：

- `src/auth/*` 继续负责 OAuth 登录、callback、token 换取、userinfo 获取和本地 session。
- `src/messages/service.js` 继续负责留言业务规则，包括创建人可信来源和本人编辑/删除权限。
- `src/messages/repository.js` 和 `src/messages/sql.js` 继续负责 BPMT 动态表数据访问。
- `src/messages/routes.js` 增加移动端友好的页面路由，但提交动作继续复用现有 POST 语义。
- `views/` 重构为移动优先模板。
- `public/styles/bpmt.css` 重写为移动优先样式，并提供宽屏兼容布局。
- `public/scripts/messages.js` 只保留必要的原生交互，例如删除二次确认和筛选区展开，不再承担弹窗装载主流程。

主要路由：

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/` | `GET` | 留言信息流首页，包含搜索、列表、分页和新增入口。 |
| `/messages/new` | `GET` | 新增留言页面。 |
| `/messages` | `POST` | 提交新增留言，沿用现有服务端创建逻辑。 |
| `/messages/:id` | `GET` | 查看留言详情页面。 |
| `/messages/:id/edit` | `GET` | 编辑留言页面，仅本人可进入编辑动作。 |
| `/messages/:id/update` | `POST` | 提交编辑留言，沿用现有服务端权限校验。 |
| `/messages/:id/delete` | `POST` | 删除单条留言，沿用现有服务端权限校验。 |

`/messages/bulk-delete` 可以暂时保留服务端路由兼容已有测试或旧入口，但不作为移动端主流程展示。批量删除不是 v2.0.0 的核心能力。

## 页面设计

### 首页

首页使用移动端信息流结构：

- 顶部 app bar：显示“留言登记”、当前 BPMT 用户和退出入口。
- 主操作区：突出“新增留言”入口。
- 搜索区：支持标题模糊和创建者筛选；在手机上默认紧凑展示或可展开，避免占满首屏。
- 列表区：每条留言以卡片展示标题、内容摘要、创建者、创建时间和更新时间。
- 卡片操作：所有留言可查看；本人创建的留言显示编辑和删除入口；非本人留言不展示可执行编辑/删除按钮。
- 分页区：移动端使用上一页、当前页、下一页等低密度控件；宽屏可展示更多分页信息。

### 新增页

`/messages/new` 是全页表单：

- 页面顶部提供返回首页入口。
- 表单包含标题和内容。
- 保存后回到首页，并通过 flash 提示“留言已新增”。
- 表单错误由服务端返回可读错误页或表单提示，不在浏览器暴露敏感信息。

### 详情页

`/messages/:id` 展示完整留言：

- 显示标题、内容、创建者、创建时间、更新时间。
- 本人创建的留言显示编辑和删除入口。
- 删除需要浏览器二次确认，提交后回首页。

### 编辑页

`/messages/:id/edit` 复用新增页的表单结构：

- 预填标题和内容。
- 保存后回首页，并通过 flash 提示“留言已更新”。
- 非本人留言不能完成更新；服务端权限校验仍是最终依据。

## 错误处理与安全

- 未登录访问业务页面时，继续由 `requireLogin` 引导到 demo 登录入口，再走 BPMT `/oauth/authorize`。
- OAuth `error`、缺少 `code`、state 校验失败、token 换取失败和 userinfo 获取失败继续进入服务端错误处理。
- 未初始化 `DEMO_MESSAGE` 表时，首页在小屏上展示清晰的初始化提示，引导运行 `npm run setup` 或 Compose `setup` 服务。
- flash、错误页和初始化提示必须在移动端首屏可读。
- 文档和页面不得输出 `client_secret`、`BPMT_API_APP_SECRET`、授权 `code`、`access_token`、密码或数据库凭据。
- 浏览器提交的创建人字段仍不可信，创建人必须由服务端当前 OAuth session 的 `userid` 决定。

## 响应式规则

- 默认样式面向手机，推荐适配宽度从 360px 起。
- 720px 以上进入宽屏布局：列表卡片可以变成两列或更宽的单列卡片，但不恢复桌面表格主结构。
- 固定操作按钮、分页和表单控件需要稳定尺寸，避免文字溢出或点击目标过小。
- 弹窗不再作为新增、查看、编辑主流程；`dialog` 相关代码可删除或降级为非核心辅助。

## 发布边界

v2.0.0 可以作为一次 UI/H5 体验版本发布。发布说明应强调：

- OAuth 协议能力未变化。
- Docker Compose 运行方式和环境变量语义保持兼容。
- 主要变化是移动端信息流首页和独立新增、查看、编辑页面。
- 已知限制是批量删除不再作为移动端主流程展示。
